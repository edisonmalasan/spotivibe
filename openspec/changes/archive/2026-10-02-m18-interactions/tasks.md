# Tasks

## 1. The local-meaning guard, before any binding

- [x] 1.1 Implement `keyHasLocalMeaning(target)` as a **pure function over an event target**, covering `input`, `textarea`, `select`, `[contenteditable]`, `[role="slider"]`, `[role="spinbutton"]`, a `[role="dialog"]` subtree, and a `[role="menu"]` subtree — verify: a test per surface type asserting `true`, plus tests asserting `false` for a plain element, for a non-guarded role, and for a `null` target. **The predicate is structural, not focus-aware**: an unfocused `<input>` still returns `true`, because "decidable from the target alone" is the property that makes it testable, and a focus-aware rule could not be (spec: `keyboard-shortcuts` — "No shortcut fires while a text field has focus"; "No shortcut fires inside editable content"; "A slider keeps its own arrow keys"; "The guard is decidable from the target alone").
- [x] 1.2 Prove the guard reads **only** the target — verify: a test that the same element yields the same answer with application state changed underneath it, so the guard cannot have consulted a store (spec: `keyboard-shortcuts` — "The guard is decidable from the target alone").
- [x] 1.3 Treat `contenteditable="false"` as **not** editable, because the platform does and because treating a read-only block as a guard would disable every shortcut anywhere one is on screen — verify: a test asserting `false` for `contenteditable="false"`, and `true` for a bare `contenteditable` and for `contenteditable="true"` (spec: `keyboard-shortcuts` — "Read-only editable content does not suppress shortcuts").
