# Proposal: Listening insights (history, stats, streaks) and Smart Mixes

## Why

The app now *keeps playing* (M10) and already records every listening event locally, but it can tell the listener nothing about their own listening: there is no history surface, no sense of time spent or favorite artists, no streak, and the Home feed's "Smart Mixes" section is a placeholder that only checks whether enough local signal exists. ROADMAP M11 asks for exactly these insights, and its acceptance criteria are all about properties this architecture makes achievable and must now prove: stats recomputable from local history, deleting history updating them, and mixes working with no server-side identity.

None of it needs a provider capability that does not exist. The M8 discovery feed already serves a language-interleaved `mix` kind, the M7 library and M8 history datasets already hold the signals, and M10's derived taste profile already weights those signals. M11 is a reading-and-composition milestone over data the product owns.

## What Changes

- Add **play classification**: a documented, local rule for what counts as a completed play, a partial play, and an immediate skip, applied **at read time** over the recorded `secondsPlayed`/`durationSeconds`/`completed`/`skipped` fields. Classifying on read (rather than storing a verdict) means the thresholds can change later without a migration, and an old event is re-read with today's rule.
- Add **local stats**, all derived from the history dataset on demand: total listening time, meaningful play count, top tracks, top artists, a language/genre/category breakdown where metadata supports it, completion/skip summaries, and **listening streaks** (current and longest), with the local-time day boundary handled explicitly.
- Add a **History page** at `/history`: recent events grouped by day, each entry linking to the artist and album surfaces M9 shipped, plus a way to clear the history (which the M7 data controls already own).
- Add **Smart Mixes**: a persisted, locally generated mix with a stable name and identity for a period, 20+ tracks where the provider supports it, deduped against everything already in the mix and the local played set, composed language-aware from the M10 profile, and refreshable. Mixes are generated by composing the **existing** `mix` discovery feed with profile-derived seeds — no new provider capability and no new API surface.
- Nothing derived from the listener leaves the device: stats, mixes, and their inputs are local, and a mix is reproducible from the local profile alone.

## Capabilities

- **New Capabilities**:
  - `insights` — play classification, the local stats derivation, listening streaks, and the History surface, including how clearing local history changes what all three report.
  - `mixes` — Smart Mix generation, identity and naming, composition and dedupe, language awareness, refresh behavior, and their local-only guarantee.
- **Modified Capabilities**:
  - `discovery` — the Home "Smart Mixes" section lists the real, locally generated mixes instead of a signal-presence placeholder.
  - `local-data` — the mix dataset and the confirmation that listening history is included in export by default.

## Impact

- **New client code**: `features/insights/{classifyPlay,buildStats}.ts` (pure), `stores/mixStore.ts`, `features/mixes/{mixNaming,generateMix,MixList}.tsx`, `app/history/page.tsx` + `features/history/HistoryView.tsx`, and a mix section component for Home.
- **New storage**: one IndexedDB store for mixes (so a mix keeps its identity across reloads) plus its backup-envelope entry, derived-data marked. No change to the history schema.
- **Existing code touched**: `data/repositories/*` (the mix repository type + store), `data/backup/{schema,serialize,plan}.ts`, `features/home/HomeView.tsx` + `homeSections.ts` (the mixes section), the architecture test suite (new detectors, the backup-dataset whitelist), and the settings/data surfaces only if a control is genuinely needed.
- **No new dependencies, no new API routes, no new provider capability, no accounts, no server-side profile.**
- **Known limitation carried forward**: with an empty history, stats are empty and no mix is generated — the surfaces say so rather than inventing numbers, and the roadmap's M8 "only when enough local signal exists" rule becomes "only when there is any signal at all to build from".
