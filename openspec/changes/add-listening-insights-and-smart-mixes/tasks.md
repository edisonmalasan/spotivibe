# Tasks

## 1. Play classification

- [x] 1.1 Add `src/features/insights/classifyPlay.ts`: a pure rule over the recorded event (`secondsPlayed`, `durationSeconds`, `completed`, `skipped`) returning `completed | partial | skipped`, with documented threshold constants and a seconds-only fallback for an unknown duration — verify: unit tests cover every branch (marked completed, fraction rule, seconds rule, marked skipped, skip threshold, the boundary values themselves, unknown duration) and that a real recorded event classifies identically no matter how many times it is read.
- [x] 1.2 Assert classification is a **read-time** policy: the recorder must keep storing only raw measurements, and the thresholds must be overridable per call so a changed rule re-reads history without a migration — verify: a test changes the thresholds and re-classifies the same event to a different verdict with no write to the history dataset, and the recorder's event shape is unchanged.
- [x] 1.3 Record the measurements the rule reads (added during implementation): the recorder writes `secondsPlayed` from the engine's reported position and a `completed` marker when a step reaches the track's end, patched onto the already-recorded event when the step ends (next step, detach, or `pagehide`). Without this the M8 recorder's `secondsPlayed: 0` makes every real event classify as a skip, so the statistics, streaks, and "no signal, no mix" rules above would be unsatisfiable in a real browser — verify: repository/store update tests, recorder tests proving a 180s-of-240s step reads as `completed` through `classifyPlay` and that `buildStats` then reports a non-zero `playCount`, a step that never moved stays at zero seconds, a failed measurement write keeps the event, and a measurement is never taken from another track's position.

## 8. Corrections from the M11 verification pass

Found by the independent read-only verification against these artifacts and fixed before the Apply PR. Each is a place where the implementation had drifted from the approved contract, not a style preference.

- [x] 8.1 `"replace"`-importing an envelope without the mixes dataset left local mixes untouched, so a replace wiped every other dataset but not this one. `SUPPORTED_DATASETS` in `src/data/indexeddb/apply.ts` now includes `STORE.mixes`. verify: `tests/import-apply.test.ts` asserts a pre-M11 envelope replace-import leaves `mixes.list()` empty, while merge-import leaves it untouched.
- [x] 8.2 The skip threshold was inclusive (`<= 10s`) while the requirement says "fewer than the documented skip threshold" and design decision 1 says "under" it. The rule is now exclusive and the boundary test reads the requirement's way. verify: `tests/classify-play.test.ts` pins 9.999s skipped, 10s partial.
- [x] 8.3 A second "Build a mix" in the same period silently replaced the mix's name, because `generateMix` wrote a fresh record over an identity the listener already had. It now takes the refresh path. verify: `tests/generate-mix.test.ts`, "treats a second generation in the same period as a refresh of that mix".
- [x] 8.4 The History surface claimed "the local record" while rendering the 50-event store window. The header now says "the most recent plays ... up to 50 at a time", and a negative test asserts the surface never renders a total, ranking, or completeness claim. verify: `tests/history-view.test.tsx`.
- [x] 8.5 The mix surface had no entry point anywhere in the app: Home's shelf is list-only, so `generateMix` was unreachable from the UI. The full surface is mounted on `/history` (design decision 8) and the Home shelf renders its authored description again. verify: `tests/routes.test.tsx` and `tests/mix-list.test.tsx`.
- [x] 8.6 Coverage gaps closed for scenarios that had no test at all: an envelope with no mixes key (`tests/backup-import.test.ts`), the mixes merge rule in both directions and its convergence (`tests/import-apply.test.ts`), the recorded generation period and same-period convergence, reproducibility from local data alone, and clearing local data changing future mixes (`tests/generate-mix.test.ts`), plus clearing from the surface resetting the statistics end-to-end (`tests/routes.test.tsx`).
- [x] 8.7 Dead state removed rather than left in place: `mixStore.activeId`, `mixStore.remove`, and the unreachable `"ready"` status; `MixDraft` unexported; stale comments corrected in `verdictCounts`, `buildStats.hasSignal`, and the architecture route test.
- [x] 8.8 The `discovery` delta amended: the Smart Mixes section keeps its header (title plus authored description) but lists mixes as a named list rather than a horizontal card shelf, because a mix is a collection rather than a single track. Rationale recorded in design decision 8.
- [x] 8.9 `vitest.config.mts` carries a suite-wide `testTimeout: 20_000` from the M11 work, for cold fake-indexeddb hydration. It lengthens failure latency and weakens no assertion; recorded here so the infrastructure change is visible in the change rather than only in a commit body.
- [x] 8.10 **Pre-existing import bug found by this change's own tests.** `applyImport` opened every object store unconditionally while the transaction only spanned the stores that had writes, so any import that wrote only *some* datasets raised a `NotFoundError` and aborted (and rolled back). It survived because every pre-M11 fixture and the M2 evidence run imported envelopes that wrote every dataset; the M11 mixes cases, where an export of a device with a mix and a session but no likes or playlists writes only some, are the first shape that hit it. Each store is now opened only when it has a write. verify: `tests/import-partial-write.test.ts` covers a partial merge, an all-zero write plan, and a partial replace; the M11 evidence run's export -> reset -> import round trip now passes.
